# LeakChain India | Next phase: visual research interface

Status: product design only, not yet implemented. No GitHub publication.

## Primary objective

Let a reader discover all 50 source-linked incidents, inspect a richly visualized sequence of reconstructed stages, open the underlying claims and articles, understand evidentiary uncertainty, and compare mechanisms across the corpus without assuming that a graph proves causality or guilt.

## Recommended architecture

- Static and privacy-conscious web application using React + TypeScript + Vite, with TanStack Table for faceted searching, and React Flow for an interactive reconstructed-event canvas. Charts can be implemented with Observable Plot or Recharts. No backend is necessary for a 50-case dataset.
- Read-only data served from `ui_data/browser_bundle_v0_9.json`, `ui_data/search_index_v0_9.json`, and `ui_data/chart_facets_v0_9.json`, generated by `python src/export_ui_data.py`. Never edit those by hand; regenerate after research CSV changes.
- URL-addressable case views at `/incidents/LCI-0001`; research categories, search queries and selected charts represented in shareable URLs.
- Keyboard navigation, colorblind-safe event-type coding, graceful mobile layouts, accessible tooltips, and reduced-motion defaults. A user's search and filter work offline after initial static load.

## Interface 1: Overview and discovery

1. At top: 50 incident episodes, 161 registered documents, 203 reconstructed events, 220 evidence claims, alongside conspicuous text that this is a purposive media-document corpus with allegations and unverified source independence.
2. Free-text search across case labels, states, coded mechanisms, safe event summaries, and statuses.
3. Facets for state, LC category, acquisition code, evidence/status, content modality, reported circulation scope, event type and number of sources.
4. Graphs for category composition, state distribution, evidence stage distribution, reported/unknown dates, and circulation scope. **Never** label incident counts as prevalence or crime rates.
5. Case cards linking to detail pages, showing safe descriptive labels, categories, documentation level, number of unresolved coding conflicts and reported source count.

## Interface 2: Interactive incident reconstruction

**Dual synchronized views:**

- Narrative timeline with numbered event cards, anchored to records, claims, dates or the label `Underlying date unknown`.
- React Flow directed schematic arranged by display order, with nodes for recording/placement, acquisition, synthetic generation, coercive threat, dissemination, complaint, investigation, and judicial response. Edges explicitly labelled `narrative display order only` unless separately encoded transmission edges are later added with evidence.
- Clicking an event reveals its individual source-attributed claims and precise source locators, allegation/procedural/journalistic status, and analytical limits.
- Clickable original reporting and official court sources, never previews or links to exploited intimate material.
- Distinct visual states for: threatened sharing, limited sharing, publicly reported posting, and commercial circulation allegations. No default inference that threats were carried out.
- Contested claims panel compares source-specific versions without automatically choosing a winner or averaging incompatible counts.
- Document lineage drawer distinguishes publication count from independently corroborated facts. Primary bail or filing records support court procedure only.

## Interface 3: Compare and analyze

- Compare two to four incidents side by side using normalized event stages, acquisition method and documentation.
- Faceted plots of event types, acquisition categories, content modalities, states and available date precision.
- Download filtered tables as JSON and CSV, with sources and research notes preserved.
- Evidence-quality panel: reported-event dates vs unknown dates; source-count vs independent-origin qualification; unresolved contradictions; share of procedural court records.

## Evidence and visual safety policy

- No imagery from incidents, account handles, victim identifiers, source-media previews, or unverified suspects' personal records.
- No online transfer paths presented as confirmed trafficking routes without primary evidence.
- Prominent human-readable caveat: alleged offence ≠ court finding; separate publishers ≠ independent fact witnesses; node order ≠ chronology when date unknown; reports are selected cases not population prevalence.
- `ui_data` is generated from data CSVs, not an independently verified new data set.

## Future acceptance tests

- Every visual event opens one or more existing, correctly linked claims with registered source IDs.
- All 50 cases are reachable via search and filters; no filters drop cases accidentally.
- Unknown dates never appear on a dated scale as fabricated timestamps.
- Contradictions are visible on the case page, including LCI-0008, LCI-0016, LCI-0019 and LCI-0041.
- Full keyboard access and mobile tests, no external tracking by default.
- The UI remains unpublished until the researcher expressly approves a combined audit and design release.
